===== ROUND 1: CODEX (codex exec, read-only) =====
The evidence supports close **net agreement**, but not the headline completeness guarantee.

1. **Offsetting errors remain unresolved.** Equal bot-hour counts can hide loss plus duplication within that hour. Only 16/640 bot-days per stream receive seeded multiset reconciliation. Board-d-Comet 10-11 explicitly has nine losses plus one extra. Thus neither “≥99.99% retained” nor “all loss at midnight” follows fleet-wide. Reconcile every bot-day, separating missing and extra multiplicities. Even `(timestamp, kind)` can collide; compare canonical payloads or event IDs. The reported 12,000 matching bot-hours are not reproduced by `compare.py`, which emits net hourly totals.

2. **Artifacts disagree.** `digest.txt` gives board-d-Comet 10-11 **19,081** file rows; its drill and `summary.json` give **19,080**. Resolve this provenance discrepancy before accepting precision to individual rows. The “at most three per-kind deficits outside 10-07” claim also uses whole-window totals that include offsetting 10-07 surpluses; individual daily deficits already exceed three.

3. **10-07 retransmission is plausible, not fully established.** `botday.py` correctly computes positive multiplicity differences, but calls every excess at an existing key a duplicate without comparing payloads. Keys absent from files do not prove crash loss. “Over-counted, not under-counted” is misleading: board-b-Comet has two missing rows alongside ten extras. Deduplicating solely by timestamp/kind risks deleting legitimate simultaneous events.

4. **Mapping negatives exceed the classifier’s capability.** Planted probes call `classify()` directly, bypassing `walk()`. Nonempty objects lose their parent type; the advertised `bot.name <- dict` control therefore does not test actual census behavior. I reproduced `flat_mapping()` losing explicit `dynamic:false` on an object without `properties`. Type-only checks cannot validate date strings, numeric bounds/coercion, or flattened depth limits; descendants of flattened fields are accepted unconditionally. [Elastic’s flattened documentation](https://www.elastic.co/docs/reference/elasticsearch/mapping-reference/flattened) documents those limits. Use complete planted rows through the entire pipeline and mapping-compatible parsing tests.

5. **Rejection evidence needs narrower wording.** There were **27 strict rejections on 10-07**, so zero across the requested window is false. The 31/31 and 27/27 counter/log matches are valuable controls for later observed zeros. However, `fbjournal.py` ignores individual `cat` failures, silently skips malformed metric records, and has only 2,878 snapshots on 10-10. Verify coverage and processing-time versus event-time boundaries. `_ignored` has no positive control, correctly acknowledged by the report.

6. **Several mechanics are sound, with limits.** Reservoir sampling is correct; half-open cutoff handling works for canonical UTC timestamps. Composite terms preserve timestamp values, with appropriate `after_key` pagination. But `ts_ms()` rounds submillisecond values and mishandles offsets; validate timestamp format. `botday.py` ignores the run cutoff, making current-day drills incomparable.

7. **Source equality is sample-only.** The matcher controls establish visibility, not content-comparison sensitivity. A reproduced bug treats changed string `"null"` as a dropped null. Python equality also conflates some boolean/numeric values. Fix these and plant mutations. The report additionally claims exact `skill.args` equality despite only 1,598/1,600 equal comparisons.

A non-null unmapped `llm.brain` would reject the document under [strict mapping](https://www.elastic.co/docs/reference/elasticsearch/mapping-reference/dynamic), conditional on confirming the actual write index. The census denominator is eligible window rows, not all scanned lines; neither side measures events lost from both.

VERDICT: NOT-COMPLETE-ENOUGH -- reconcile gross loss and extras fleet-wide, resolve artifact discrepancies, repair classifier and equality controls, verify rejection coverage, and map llm.brain before deployment.
