# vegclear-01show: wild vegetation in an open record cell is dug (2026-11-19)

Branch `vegclear-01show`, built on a714d15e9 (T11 bundle release 1). It ships after T11 release 1.

## Why

- **T11 rig run 11.** 11,69,-30 held a brown_mushroom. A mushroom is not in `PLACEABLE_INTO` (townplan.mjs:38), so a placement cannot replace it. It is not in `FOREIGN_CLEAR` (buildrun.mjs:162), so the foreign pass will not dig it. The cell read `blocked` 63 times, with 96 cells waiting on it.
- **The showcase, 11-18** (ci2 `showlogs-1118d` and the 12:36Z region): 38 of the 427 stuck or blocked tidy cells hold a spruce sapling.

## What changed

- `buildrun.mjs` gains **`VEG_CLEAR`**: mushrooms, small flowers, saplings, sweet berry bush, pink petals, moss carpet, short and tall grass, ferns.
- An **open record cell** holding one of these is dug like scaffold (`kindAt`, then `vegForeign`).
- **Guarded by the cell, not the name.** It is never dug from a cell whose role's palette names vegetation (`roleNamesVeg`, following `$role` entries).
- `FOREIGN_CLEAR` itself is unchanged. The overburden, cover and seal digs read `FOREIGN_CLEAR` and dig non-cells above a cell, which can include a neighbour's flower. They do not take the new list.

## Designs that place these names (the audit)

Every file was checked with grep, and each palette was checked in code with `roleNamesVeg`.

| File | What it places | Roles that hold vegetation |
|---|---|---|
| park.mjs | flowers, tall flowers, shrubs, saplings, hedges, meadow `short_grass` | `flower0..3`, `tall0..1`, `shrub`, `sapling0..3`, `hedge`, `meadow` (the tidy palette carries the same roles) |
| decorator.mjs | border plants, pots, blooms (`SMALL_FLOWERS`, fern, short and tall grass, saplings) | palette built per record from these lists |
| cottage2.mjs | flower boxes (`BOX_PLANTS`) | palette built per record from these lists |
| forest.mjs | its planting roles | `plot` |
| upkeep.mjs | its replant role | `sapling` |
| treefarm.mjs | its species (`FARM_SPECIES`) | palette built per record |
| tidy.mjs | replants (`SAPLING_OF`) | the record's `replant` list, not cells |

- In every case above, the design's own plant cell is a role that names vegetation, so `vegForeign` never digs it.
- **No design places these names:** civic, townstyle, landmark, the cottage blueprints (`blueprints/*.json`), citywall, the pattern books.

## Review round 1 (Codex): 2 blockers, fixed

1. **Another project's sapling could be dug.** A forest, upkeep or tidy replant can stand in a cell that another record names as a fill. The dug set (`VEG_DIG`) therefore never takes a sapling. The showcase's 38 stuck sapling cells are not covered by this piece. They are probably replants planted into tidy fill cells, a conflict between two plans for the owner, not wild growth.
2. **A refused dig on short grass could spend the attempts a placement needed.** Short and tall grass and ferns are already replaced by a placement (`PLACEABLE_INTO`), so they are never dug.
