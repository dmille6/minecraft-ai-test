---------------------------------------------------------------- Codex r1, verbatim
Review of the specified commits. The full suite was blocked by the read-only sandbox's inability to create temporary files; 76 in-memory fixture cases passed. Findings reference the committed versions.

- **P1 — Historical rows mask newly silent sources.** `scripts/host/hazardmap/hazardmap.py:544`: `MUST_SPEAK` checks the entire history since October 8. Once a source has spoken, a subsequent rename can remain undetected indefinitely. Renaming only recent `_death` rows reduced the fixture's deaths from 33 to 29 without `Blind`, compromising both map and value denominators. **Fix:** check source health over a recent bounded window with positive activity controls, reconcile deaths against independently recorded death-site rows, and test renames beginning midway through history.

- **P1 — Wetness has no blind guard.** `scripts/host/hazardmap/hazardmap.py:253`: `_water_float` is queried with `allow_zero=True` but never checked for silence. Renaming it removed the fixture's water-pit hazard without raising; wet spells became "dry" exclusions. **Fix:** include wetness in source-health controls and cache recount validation, and add a renamed-wet-source mutant.

- **P1 — Seed metadata mixes different world generations.** `scripts/host/hazardmap/hazardmap.py:1247`: the seed comes from the staged backup, while creation time comes from the current live world. A reseed between backup and verification creates a segment with the old seed and new birth time. An injected example accepted this combination and resolved a new-world row to the old seed. **Fix:** capture generation identity and creation metadata with the backup; refuse mismatched staged/live generations. Bound seed resolution to the verified observation horizon rather than extrapolating indefinitely.

- **P1 — Incomplete probes report absence.** `scripts/host/hazardmap/hazardmap.py:1105`: mixed generated/missing chunks pass the initial checks, and undecodable block states returning `None` are treated as negative evidence. Both cases reproduced `absent`. Additionally, `verify()` at line 1293 ranks `absent` above `unknown`, concealing incomplete multi-cell checks. Consumers are instructed to discard absent hazards. **Fix:** emit absence only when every required cell/probe was successfully checked; otherwise preserve uncertainty unless positive evidence establishes presence.

- **P2 — Old absence applies to expanded hazards.** `scripts/host/hazardmap/hazardmap.py:702`: verification results are joined solely by stable hazard ID. New evidence can expand a cluster while retaining that ID, so yesterday's absence suppresses newly observed cells. Extending the fixture's lava cluster reproduced this. **Fix:** attach a probe/evidence fingerprint and observation cutoff to results; invalidate negative results when covered cells change or newer evidence arrives.

- **P2 — Unrelated crashes count as successful mutant kills.** `scripts/host/hazardmap/test_hazardmap.py:778`: any exception anywhere in `all_cases()` counts as killing the named case. The UNKNOWN-corridor mutant demonstrates this: its compact assertion remains satisfied (`[0]` is unchanged), but a later source-control exception earns the kill. **Fix:** execute and attribute each mutant to its named case, fail on unrelated exceptions, and make the compact assertion check the changed tuple discriminator.

Verdict: one P1 has to be fixed before install. The guard against a renamed or silent source is checked over the whole window since 10-08, so a rename after install will quietly shrink the map. The suite gave 147 cases, 0 failed, in about 40 s. I also ran some extra input and code mutants from my scratchpad; the results are quoted in the findings below.

**P1 (must fix before install)**

1. **The silent-source and unparsed guards only look at the whole window since 10-08, so they lose strength every day.** `hazardmap.py:544-547` raises only when a MUST_SPEAK source has zero rows across *every* validated day. `:548-552` uses one 2% unparsed share pooled over the same window. After install, a kind renamed by a bot deploy still has 17+ days of history behind it, so the build never raises, and that is exactly how this tool gets blind.
   - Reproduced: I renamed `_death` -> `_died` on the last fixture day only. The build succeeded with 32 deaths instead of 33 and raised nothing.
   - The existing blind mutant renames every day, which is why it passes.
   - The same pooling weakens `death_site_control` (`:781-801`, aggregate 90% / 95%).
   - Fix: run the MUST_SPEAK, unparsed-share and death-site checks on the most recent closed validated day, or the last 2-3 for rare sources, as well as over the whole window; add a per-day check that `death` and `site` counts are equal (they pair 630/630, so renaming either one breaks it the same day); add blind mutants that change only the last fixture day, and require them to raise.

**P2 (should fix)**

2. **Rows can fold into the wrong seed.** `measure_worlds` (`:1243-1248`) reads the seed from the *staged* `level.dat` but `created` from the *live* `world/datapacks` birth time. `Seeds.from_verify` (`:352`) leaves the current segment open-ended. A reseed between the 03:15Z backup and the verify run records the new world under the old seed. A reseed after verify misfolds that world's rows into the old seed until the next good verify (up to 72 h, because `check_fresh` allows it). Fix: end the open segment at the backup-line time and exclude later rows; in `measure_worlds`, flag or skip a world whose live datapacks birth is later than the backup; publish a `measured_at` per world; optionally a hashed seed for a live check.
3. **Validated rows outside a world's lifetime are dropped quietly.** `seed_for` (`:562-569`) raises only for `unknown_world`. Reproduced: moving board-a's `created` to 10-15 built a map that just counted the dropped rows under `excluded:*outside_world_lifetime`. Fix: in the validated window, raise when `outside_world_lifetime` or `quarantine` rows go over a small floor.
4. **Other blind inputs the zero rule does not cover:** `_water_float` (`:253`) is not guarded (renamed -> every maroon spell becomes `marooned_dry`, all water pits disappear quietly); a `void` validated day (`:230-232`, skipped at `:531`) is ignored; `load_days` (`:323-330`) skips files of another schema and never checks the days are contiguous. Fix: make the wet histogram a guarded source, raise on a void or missing validated day, and check the cache covers every day from history_since to now except 10-07.
5. **The terrain control is measured but never enforced.** `terrain_control` (`:1172-1198`) is only copied into `controls.terrain` (`:773`), yet merging worlds by seed rests entirely on it. Fix: raise in build (or keep worlds separate) when `within_seed.min_agreement < 0.99`, or when too few cells were comparable.
6. **The value chance null does not keep the death density around the home** (`:872`, `:891`). All 10 shared-seed worlds have the same home, and deaths crowd around it. Moving priors 48 blocks pushes them out of that dense area; the spread across the 8 directions (0..19) shows the result depends on where the shift lands, so "mean 6.2" understates chance. Fix: add a null that keeps distance from home (rotate priors 90/180/270 about the seed's home, or singleton-seed priors translated by the difference between homes) and report it next to the 48-block shift.
7. **The "42 beyond per-world memory" applies the 24 h lag to own-world priors too** (`:842`). keepout's per-world memory updates live, so an own-world prior from an hour ago should count. Fix: use lag 0 for `hit_same`. Expect roughly 38-41.
8. **`deaths.cells` is the 16 cells first in coordinate sort order, with no total** (`:651`, `:661`). Probes also take `cells[:4]` (`:916`). A pool with 188 deaths hands lavasight its 16 west-most cells. Fix: sort by count, then most recent; add `cells_total`; probe the top-count cells.
9. **The board-d pit label is stronger than its evidence** (report 0.3, 4, "Trap shapes do not transfer"). "Absent in all 10 because poolescape-01's digs changed them" depends on a check that finds the pit at only 4.75% of its own targets; there is no positive control on a copy taken before poolescape-01. Fix: show the check reading `present` on an older board-d copy, or reword.
10. **The test harness credits a crash as a kill** (`test_hazardmap.py:800-802`): one BEHAVIOUR mutant ("corridor UNKNOWN skipped") kills only by crashing; a mutant that fails to compile would also score as killed. Fix: score a kill only when the named case fails.
11. **Two value guards have no killing test.** Removing the `same_kind` filter survives; dropping the seed from value's grid key is caught only by the own-world count. Add a different-world, different-seed death at the same cell, and add both mutants.
12. **The alarm is not surfaced.** `check_line` (`:1490`) is not wired into the fleetstatus header. Memory says "alarms must surface in the fleetstatus header". Wire it in at install, or list it as an install step.
