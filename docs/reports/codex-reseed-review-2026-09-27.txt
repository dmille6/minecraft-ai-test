# Working rules for this repo

Short list. Every rule here exists because breaking it cost real time, and the
evidence is named so you can judge it rather than obey it.

**This file is a tripwire, not a control system.** Where a rule here could be
made mechanical instead, that is the better fix and this file should shrink.
`ZeroLooksWrong` is the model: it does not ask you to remember, it raises.
Two rules earned their mechanism already — `npm test` is now the only test
command, and `Events.rate()` no longer has a fleet-size default to get wrong.

The failure this project keeps repeating is **believing a cheap negative**. A
zero from a query, an empty mutant, a short window, a green run of the wrong
runner. Most of the rules below are guards against exactly that.

The second failure is **never closing**. Analysis is unbounded here and
validation is one change at a time; the queue can only grow. The rule below is
the guard, and `check-open-loop.py` is its mechanism.

---

## Done means read on the fleet, not merged

A change is DONE when all five have happened:

```
merged -> deployed -> observed on the fleet -> KEEP or REVERT recorded -> memory says SHIPPED
```

Not "analysed". Not "105/105 green". Not "the plan is published". Not
"probably right". A local test proves the code does what you wrote; only the
fleet says whether what you wrote was worth writing.

**While a canary is deployed and unread, no new analysis starts.** Read it,
decide, tear it down (both steps), then take the next thing. `check-open-loop.py`
raises `OpenLoop` when the manifest declares a canary with no decision recorded
against its sha, so this does not depend on anyone remembering it.

Recording INCONCLUSIVE is a legitimate close and is often the honest one — two
readings inside the 2.36x between-pool noise band is not a result. What is
forbidden is walking away with nothing written, because that is indistinguishable
from the work never having happened.

Measured 2026-09-04, and this is why the rule exists: **100 memory entries, 25
of which mention shipping anything and 17 of which correct an earlier finding.**
Five commits sat on `main` undeployed, including all three drowning fixes, while
that day produced six fresh analyses and one commit. Sixty commits were written
that week; roughly two were validated. Every one of those analyses was correct.
That is the point — being right is not the constraint, and treating "better
grounded" as progress is how a month goes by with the endpoint flat.

## Telemetry: use `scripts/lib/telemetry.py`. Do not hand-roll a query.

```python
from lib.telemetry import Events
ev = Events.load(since_minutes=180)
ev.count('drowning_route')          # raises ZeroLooksWrong on a suspicious 0
ev.by_bot('mine'); ev.where('mine', lambda r: 'water' in (r.get('detail') or ''))
```

`ZeroLooksWrong` exists precisely because a zero is usually a query bug. Pass
`allow_zero=True` only when you have already proven the query finds something.

Hand-rolled queries produced two wrong findings in one day: "84 of 84 bots
immobile" (read a `snapshot` field that does not exist in these logs — position
is at `bot.pos`), and "rideFloorDown places zero blocks" (read a filtered
failure bucket as if it were the population; it had placed 140).

- **Full walks only.** A full walk is ~4s. Seeking to the tail silently eats the
  baseline and flatters whatever changed most recently.
- **`grep -a`** — the files trip binary detection.
- **Event kinds live in `skill.name`**, position in `bot.pos`, inventory in
  `bot.inventory`, arm/pool in `exp`. There is no top-level `snapshot`.
- **`Events.rate()` requires `bots=`** — pass `bots='auto'` to count the bots
  actually present. It used to default to 40 against an 80-bot fleet.

## Test behaviour. Source-grep only for structural invariants.

Five grep assertions passed for the wrong reason in one day: matching the
comment that explains the code, an inverted assertion, a window too narrow to
see the thing it forbade, a constant asserted present but never used, and a
hardcoded ternary whose branches both still appeared in the text.

The fix each time was the same — pull the decision into an exported pure
function and test its behaviour. See `overheadBreakRisk` and `climbPrereqFor`
(reflex/scaffold) and `stairLiquid` (skills). Those cannot lie.

Source assertions ARE legitimate for things behaviour cannot reach: a skill is
registered in the dispatch table, a dangerous call is absent, a config value is
wired into the runner, an anti-regrowth guard is still dead. Those are real and
this repo needs them.

When you write one: strip comments first (this codebase's comments quote the
code they explain, so a naive grep matches the explanation), anchor on the
executable line rather than a constant's declaration, and prove it fails for the
intended reason with a mutant. A source test that has never been seen to fail is
not a test.

Never assert decision logic by matching text. Extract the decision.

## A new refusal must name a remedy the bot can perform from where it is

Four separate traps were **two individually-correct guards meeting where the bot
had no legal move**: the exit contract vs `mine`; `surface` vs the entombment
reflex; `rideFloorDown` deferring to a `mine` that correctly refuses; the
staircase bearing vs its own water check.

The bug class is not "missing remedy" — it is **local policy composition
creating a dead end**. Naming a remedy does not prove it is executable,
selected, or reachable, so all three need checking:

- **Executable from here.** "Get a pickaxe" to a bot sealed underground with no
  wood is not a remedy.
- **Reachable.** One refusal printed the correct remedy 262 times and the model
  never acted on it. Advice printed is not advice taken; if it must happen, make
  it deterministic rather than advisory.
- **Composed.** Test the refusal CHAIN, not the single guard. Every trap this
  week passed its own unit tests.
- **Traced to its fallback.** A refusal fails the call it refuses, and the skill's `catch` then does something
  with the body. Before a new refusal deploys, name every catch/fallback the refused call lands in and run the
  same guard on the fallback's own movement, with a wired test for the chain. 2026-09-15: a correct lava
  refusal failed an explore leg, and explore's fallback walked blind into the pool the refusal had named.

## Deploys

- Run the deploy script **from a copy outside the repo** — it `git reset`s the
  tree it lives in, and bash re-reads a running script by byte offset.
  `sudo cp /opt/minecraft-ai/scripts/deploy-fleet.sh /root/d.sh && sudo /root/d.sh <sha> <run_id> "<notes>" [--pool P]`
- **One canary pool, ever.** The tripper matches `canary_pool` literally; two
  canaries means three versions means a halted fleet.
- **Teardown is THREE steps** — drop-ins, clearing `canary_pool`, **and
  restarting the pool's bots**. The first two are config; neither restarts
  anything, so the bots keep running the canary code from memory and the fleet
  sits on three versions, which halts the tripper. Measured 2026-09-04: after a
  "complete" two-step teardown of placebo-b, all five bots were still reporting
  the canary build, and only the next deploy's verifier caught it. Stagger the
  restarts 12s apart, then confirm exactly two versions are live.
- **The pre-push hook blocks canary branches, and that is a false positive.**
  It refuses any push while behind `origin/main`, but a single-variable canary
  must branch from the DEPLOYED BASELINE, not from main, so it is behind by
  construction. Confirm the remote branch does not already exist — then the push
  can only create, never overwrite — and use `--no-verify` for that push only.
- A canary pool must **contain the population the fix targets**, or it shows
  nothing.
- Rare outcomes (deaths ~0.1/hour/pool) are unmeasurable on 5 bots. Use them as
  tripwires, not proof.
- **No gate reverts anything until it is calibrated.** OWNER 2026-09-15: every rule that can REVERT a canary carries
  a backtest on pseudo-canaries (`scripts/gatecal.py` for death rules, `scripts/guardcal.py` for movement and
  productivity guards) with its false-revert rate and, where a harm can be injected, its detection rate, both in
  the registration. Without the two numbers the rule is report-only. Three of four reverts on 2026-09-15 were the
  instrument: a call-count guard (explore calls -70% while gather and deposits doubled), a linkage rule scoped
  for ladder changes applied to a lava change, and a guard that refused terrain as lava.
- **A canary may bundle two changes** with disjoint diffs and separate instrument lines (rule v16 in
  docs/reports/recovery-ladder-registration.md); a REVERT on a shared line reverts both.
- **The death gate needs TWO canary deaths** (and > 1.25x the control rate) before it
  trips on its own. OWNER DECISION 2026-09-11: at ~0.05 deaths/bot-hour one unrelated
  death lands on a 5-bot pool in 90 min about a third of the time, and it reverted two
  working canaries in one afternoon (a lava swim during explore, a drowning while idle).
  One death is reported in the read and named; it is not a verdict. `canary-report.py`
  enforces the floor; the read scripts under ~/mcai-analysis say "two-death floor".

   231	    """Load (and if necessary GENERATE) the chunks a candidate will be probed in.
   232	
   233	    Probes read air in an unloaded chunk, which would score every distant

   237	    queued; generation happens asynchronously on the server thread. Probing

   239	    how busy that world happened to be -- which is how eight worlds built from
   240	    ONE seed produced two different town sites, one of them on a mountain at

   242	    deterministic.

   272	    _forceload(rcon, cx, cz, on=True)

   274	        return _score_loaded(rcon, cx, cz, stats)
   275	    finally:
   276	        # Leaving hundreds of chunks forceloaded would keep every rejected
   277	        # candidate ticking for the life of the server.
   278	        _forceload(rcon, cx, cz, on=False)

   281	def _score_loaded(rcon, cx, cz, stats):
   282	    centre_y, centre_kind = column(rcon, cx, cz)
   283	    if centre_kind != "solid":
   284	        return {"ok": False, "reason": f"centre is {centre_kind}", "y": centre_y, "stats": stats}
   285	
   286	    for dx, dz in SAMPLE_OFFSETS:
   287	        y, kind = column(rcon, cx + dx, cz + dz)
   288	        stats["sampled"] += 1
   289	        stats["ys"].append(y)
   290	        stats["kinds"].append(kind)
   291	        if kind == "water":
   292	            stats["wet"] += 1
   293	            # Water anywhere inside the platform footprint is disqualifying: the
   294	            # town is stamped there and a chest half in a lake is the failure the
   295	            # original probe was written to catch.
   296	            if abs(dx) <= PLATFORM_HALF and abs(dz) <= PLATFORM_HALF:
   297	                return {"ok": False, "reason": f"water inside the platform at {dx},{dz}",
   298	                        "y": centre_y, "stats": stats}
   299	        elif kind == "canopy":
   300	            stats["canopy"] += 1
   301	        elif kind == "void":
   302	            return {"ok": False, "reason": f"void column at {dx},{dz}", "y": centre_y, "stats": stats}
   303	
   304	    canopy_frac = stats["canopy"] / max(1, stats["sampled"])
   305	    stats["canopy_fraction"] = round(canopy_frac, 3)
   306	    if canopy_frac > MAX_CANOPY_FRACTION:
   307	        return {"ok": False,
   308	                "reason": f"{canopy_frac:.0%} of columns are canopy, so the surface "
   309	                          f"readings are treetops",
   310	                "y": centre_y, "stats": stats}
   311	
   312	    wet_frac = stats["wet"] / max(1, stats["sampled"])
   313	    stats["wet_fraction"] = round(wet_frac, 3)
   314	    if wet_frac > MAX_WET_FRACTION:
   315	        return {"ok": False, "reason": f"{wet_frac:.0%} of columns within 32 are water",
   316	                "y": centre_y, "stats": stats}
   317	
   318	    near = [y for (dx, dz), y, k in zip(SAMPLE_OFFSETS, stats["ys"], stats["kinds"])
   319	            if abs(dx) <= PLATFORM_HALF and abs(dz) <= PLATFORM_HALF and k == "solid"]
   320	    near = near or [centre_y]
   321	    relief = max(near) - min(near)
   322	    stats["platform_relief"] = relief
   323	    if relief > MAX_PLATFORM_SLOPE:
   324	        return {"ok": False, "reason": f"platform relief {relief} > {MAX_PLATFORM_SLOPE}",
   325	                "y": centre_y, "stats": stats}
   326	
   327	    # WALKABILITY, not just dryness. A dry knoll ringed by cliffs or sea strands
   328	    # every bot that leaves it, which is the entrapment this whole search is for.
   329	    for dx, dz in ((1, 0), (-1, 0), (0, 1), (0, -1)):
   330	        prev = centre_y
   331	        for step in range(8, 33, 8):
   332	            y, kind = column(rcon, cx + dx * step, cz + dz * step)
   333	            if kind == "water":
   334	                return {"ok": False, "reason": f"route {dx},{dz} hits water at {step} blocks",
   335	                        "y": centre_y, "stats": stats}
   336	            # A TREE IS NOT A CLIFF. The probe returns the treetop, so comparing
   337	            # a canopy column against ground reads every forest edge as a
   338	            # fourteen-block drop and rejects perfectly walkable land.
   339	            if kind == "canopy":
   340	                continue
   341	            if prev - y > MAX_ROUTE_DROP:
   342	                return {"ok": False, "reason": f"route {dx},{dz} drops {prev - y} at {step} blocks",
   343	                        "y": centre_y, "stats": stats}
   344	            prev = y
   345	
   346	    # LAST, because it is the most expensive check and the cheap rejections above
   347	    # eliminate most candidates before it runs.
   348	    wood, wood_n = wood_nearby(rcon, cx, cz)
   349	    stats["wood_hits"], stats["wood_sampled"] = wood, wood_n
   350	    if wood < MIN_WOOD_HITS:
   351	        return {"ok": False,
   352	                "reason": f"only {wood}/{wood_n} columns within {WOOD_RINGS[-1]} blocks are "
   353	                          f"tree; the tech tree starts at oak_log",
   354	                "y": centre_y, "stats": stats}
   355	
   356	    # A TREE IS NOT A HILL -- the same mistake the route check already makes once.
   357	    # The probe returns the TREETOP, so a flat wooded plain would show a spread
   358	    # made entirely of canopy and be rejected as unwalkable ground.
   359	    ground = [y for y, k in zip(stats["ys"], stats["kinds"]) if k == "solid"]
   360	    stats["y_spread"] = (max(ground) - min(ground)) if ground else 0
   361	    if stats["y_spread"] > MAX_TERRAIN_SPREAD:
   362	        return {"ok": False,
   363	                "reason": f"terrain spread {stats['y_spread']} over the sampled radius "
   364	                          f"> {MAX_TERRAIN_SPREAD}; bots cannot walk what they can plan",
   365	                "y": centre_y, "stats": stats}
   366	    stats.pop("kinds", None)
   367	    return {"ok": True, "reason": "ok", "y": centre_y, "stats": stats}

   370	def find_site(rcon, x0, z0, step=96, rings=5, verbose=True):
   371	    """Deterministic outward spiral from (x0,z0) until a site scores.
   372	
   373	    DETERMINISTIC IS THE POINT. All eight worlds share one seed, so the same
   374	    search from the same origin lands on the same town in every world -- which is
   375	    what makes the arms comparable. A search that depended on chance or on probe
   376	    ordering would put a different town in each world and quietly make terrain an
   377	    arm effect.
   378	    """
   379	    tried = []
   380	    for ring in range(rings + 1):
   381	        pts = [(0, 0)] if ring == 0 else _ring(ring * step, n=8 * ring)
   382	        for dx, dz in pts:
   383	            cx, cz = x0 + dx, z0 + dz
   384	            r = score_site(rcon, cx, cz)
   385	            tried.append({"x": cx, "z": cz, "ok": r["ok"], "reason": r["reason"]})
   386	            if verbose:
   387	                print(f"   {'OK ' if r['ok'] else '   '} {cx:>6},{cz:>6}  {r['reason']}")
   388	            if r["ok"]:
   389	                return cx, cz, r, tried
   390	    raise SystemExit(f"no usable town site within {rings * step} blocks of {x0},{z0} -- "
   391	                     f"tried {len(tried)} candidates; widen --rings or move --x/--z")
   392	
   393	
   394	# PINNED, NOT DEFAULTED. Every one of these is identical in all eight worlds.
   395	# A gamerule left at its default is a value that can differ between two worlds
   396	# created minutes apart under different server states, and nothing would report
   397	# it. `keepInventory` is the one with teeth: without it a death destroys the
   398	# carried inventory, which is the very quantity the retained-items endpoint
   399	# measures, and death rates are not guaranteed equal across arms.
   400	GAMERULES = {
   401	    "keepInventory": "true",
   402	    "doDaylightCycle": "true",
   403	    "doWeatherCycle": "false",     # weather is unmodelled noise the bots cannot see
   404	    "doImmediateRespawn": "true",  # a respawn screen is a bot frozen for no reason
   405	    "mobGriefing": "false",
   406	    "doFireTick": "false",
   407	    "randomTickSpeed": "3",        # vanilla default, stated so it cannot drift
   408	    "doInsomnia": "false",
   409	    "announceAdvancements": "false",
   410	    "sendCommandFeedback": "false",
   411	    "logAdminCommands": "false",
   412	}

   415	def world_rules(rcon, cx, cz, radius, cy=64):
   416	    """Gamerules and the world border, applied identically to every world.
   417	
   418	    THE BORDER IS CENTRED ON THE TOWN, not on the origin. Siting now searches
   419	    outward for dry, walkable ground, so the town is no longer guaranteed to sit
   420	    at 0,0 -- and a border centred elsewhere would hand each arm a differently
   421	    shaped world with the town off to one side of it.
   422	    """
   423	    out = []
   424	    for rule, value in sorted(GAMERULES.items()):
   425	        out.append(f"gamerule {rule} {value}")
   426	    # BOTS SPAWN AT WORLD SPAWN, NOT AT THE TOWN. With siting free to search
   427	    # outward for wood, the town can land hundreds of blocks from the seed's
   428	    # spawn point -- and every bot would begin its life that far from its chest,
   429	    # its bed and its lectern, walking through unknown terrain to reach the
   430	    # experiment. Move spawn to the town instead.
   431	    out.append(f"setworldspawn {cx} {cy + 1} {cz}")
   432	    out.append(f"worldborder center {cx} {cz}")
   433	    out.append(f"worldborder set {radius * 2}")     # the command takes DIAMETER
   434	    out.append("worldborder warning distance 0")
   435	    out.append("worldborder damage amount 0")       # the border stops bots; it must not kill them
   436	    out.append("time set day")
   437	    out.append("weather clear")
   438	    return out

   441	def town_plan(x, y, z):
   442	    """The town, relative to the probed surface. One list, four worlds."""
   443	    cmds = []
   444	    # A flat stone platform. Terrain-independent footing means the bots' walk
   445	    # home ends the same way in every world even where the ground differs.
   446	    cmds.append(f"fill {x-6} {y-1} {z-6} {x+6} {y-1} {z+6} minecraft:stone_bricks")
   447	    cmds.append(f"fill {x-6} {y} {z-6} {x+6} {y+3} {z+6} minecraft:air")
   448	
   449	    # Deposit chests, at home centre.
   450	    cmds.append(f"setblock {x} {y} {z} minecraft:chest")
   451	    cmds.append(f"setblock {x+1} {y} {z} minecraft:chest")
   452	
   453	    # Beds. Five per arm, one per bot, spaced so two bots never contend.
   454	    for i in range(5):
   455	        cmds.append(f"setblock {x-4+i*2} {y} {z+4} minecraft:red_bed[part=foot,facing=north]")
   456	        cmds.append(f"setblock {x-4+i*2} {y} {z+3} minecraft:red_bed[part=head,facing=north]")
   457	
   458	    # Torch perimeter. Mob spawning inside the town is a death source that has
   459	    # nothing to do with memory, and it would land unevenly across arms.
   460	    for d in range(-6, 7, 2):
   461	        for cx, cz in ((x+d, z-6), (x+d, z+6), (x-6, z+d), (x+6, z+d)):
   462	            cmds.append(f"setblock {cx} {y} {cz} minecraft:torch")
   463	
   464	    # THE LECTERN -- the board. Its position becomes BOARD_X/Y/Z, and the
   465	    # proximity gate in board-visit.mjs measures from exactly here.
   466	    bx, by, bz = x + 3, y, z
   467	    cmds.append(f"setblock {bx} {by} {bz} minecraft:lectern")
   468	
   469	    # A stocked torch chest, so "no torches" is never the reason an arm's bots
   470	    # die more than another's.
   471	    cmds.append(f"setblock {x-1} {y} {z} minecraft:chest")
   472	    cmds.append(f'item replace block {x-1} {y} {z} container.0 with minecraft:torch 64')
   473	    cmds.append(f'item replace block {x-1} {y} {z} container.1 with minecraft:torch 64')
   474	
   475	    cmds.append(f"setworldspawn {x} {y+1} {z}")
   476	    cmds.append(f"forceload add {x} {z}")        # town stays loaded; bots respawn into it
   477	    return cmds, (bx, by, bz)

   480	def main():
   481	    ap = argparse.ArgumentParser()
   482	    ap.add_argument("arm", choices=sorted(ARMS))
   483	    ap.add_argument("--x", type=int, default=0)
   484	    ap.add_argument("--z", type=int, default=0)
   485	    ap.add_argument("--dry-run", action="store_true")
   486	    ap.add_argument("--step", type=int, default=96,
   487	                    help="blocks between candidate centres in the spiral")
   488	    ap.add_argument("--at", metavar="X,Z",
   489	                    help="stamp at these coordinates instead of searching. Used for worlds "
   490	                         "2..N so all eight get the site the first search found -- and it is "
   491	                         "re-scored here, so a world that disagrees refuses rather than drifts")
   492	    ap.add_argument("--force", action="store_true",
   493	                    help="re-site a world that already has a town (only after wiping it)")
   494	    ap.add_argument("--border", type=int, default=1950,
   495	                    help="world border RADIUS in blocks, centred on the chosen town")
   496	    ap.add_argument("--rings", type=int, default=5,
   497	                    help="how far out to search before giving up")
   498	    a = ap.parse_args()
   499	
   500	    props = ROOT / a.arm / "server.properties"
   501	    if not props.exists():
   502	        raise SystemExit(f"{props} not found -- run provision-block2.sh first")
   503	    conf = dict(l.split("=", 1) for l in props.read_text().splitlines()
   504	                if "=" in l and not l.startswith("#"))
   505	    port = int(conf.get("rcon.port", BASE_RCON + ARMS[a.arm]))
   506	
   507	    # SITING IS NOT IDEMPOTENT, so it must not be repeatable by accident.
   508	    #
   509	    # Every run STAMPS a town, and a stamped town changes the terrain the scorer
   510	    # reads. Running this three times on one world produced three towns in three
   511	    # different places -- the second search rejected the site the first had built
   512	    # on, and the third rejected both. The worlds stayed identical to each other
   513	    # only because the mistake was made uniformly, which is luck, not design.
   514	    marker = ROOT / a.arm / "TOWN-PLACED.json"
   515	    if marker.exists() and not a.force:
   516	        print(f"  {a.arm} already has a town (see {marker}). Re-running would stamp a\n"
   517	              f"  SECOND one and move the site. Use --force only if the world was wiped.")
   518	        print(marker.read_text())
   519	        return
   520	
   521	    rcon = Rcon("127.0.0.1", port, conf["rcon.password"].strip())
   522	    if a.at:
   523	        # SEARCH ONCE, STAMP EIGHT TIMES.
   524	        #
   525	        # All eight worlds share one seed, so they are the same terrain and the
   526	        # answer cannot legitimately differ between them. Searching each one
   527	        # independently ran the race eight times and lost it: two worlds landed
   528	        # on a mountain at y=119 while six took a plain at y=72, because chunk
   529	        # generation is asynchronous and the probes did not always wait.
   530	        # Reusing the coordinates makes identical worlds identical BY
   531	        # CONSTRUCTION rather than by hoping eight searches agree.
   532	        cx, cz = (int(v) for v in a.at.split(","))
   533	        _forceload(rcon, cx, cz, pad=48, on=True)
   534	        site = score_site(rcon, cx, cz)
   535	        tried = [{"x": cx, "z": cz, "ok": site["ok"], "reason": site["reason"]}]
   536	        if not site["ok"]:
   537	            raise SystemExit(f"{a.arm}: the site given by --at scores {site['reason']!r}. "
   538	                             f"Identical seeds must score identically -- refusing to stamp a "
   539	                             f"town somewhere this world says is unusable.")
   540	        print(f"  using the site found for the first world: {cx},{cz}")
   541	        y = site["y"]
   542	    else:
   543	        print(f"  searching outward from {a.x},{a.z} for a dry, walkable, level site")
   544	        cx, cz, site, tried = find_site(rcon, a.x, a.z, step=a.step, rings=a.rings)
   545	        y = site["y"]
   546	    st = site["stats"]
   547	    print(f"  chose {cx},{cz} at y={y}: relief {st.get('platform_relief')}, "
   548	          f"{st.get('wet_fraction', 0):.0%} wet within 32, "
   549	          f"rejected {sum(1 for c in tried if not c['ok'])} candidate(s)")
   550	    # The town is forceloaded for good: bots walk home to it, and a home that
   551	    # unloads is a home the deposit walk cannot finish at.
   552	    _forceload(rcon, cx, cz, pad=16, on=True)
   553	
   554	    cmds = world_rules(rcon, cx, cz, a.border, cy=y)
   555	    plan, (bx, by, bz) = town_plan(cx, y, cz)
   556	    cmds += plan
   557	    for c in cmds:
   558	        if a.dry_run:
   559	            print("   would:", c)
   560	            continue
   561	        out = rcon.run(c)
   562	        # Minecraft reports failure in prose with a 200 OK, so the only way to
   563	        # know a block was not placed is to read what it said.
   564	        if re.search(r"error|failed|Unknown|cannot|expected", out, re.I):
   565	            print(f"   !! {c}\n      -> {out}", file=sys.stderr)
   566	
   567	    payload = json.dumps({"arm": a.arm, "home": [cx, y + 1, cz],
   568	                      "board": [bx, by, bz], "rcon_port": port,
   569	                      # The siting decision, recorded so it can be audited and
   570	                      # reproduced. Terrain differences between arms would be a
   571	                      # confound; this is the evidence that there are none.
   572	                      "gamerules": GAMERULES, "border_radius": a.border,
   573	                      "siting": {"requested": [a.x, a.z], "chosen": [cx, cz],
   574	                                 "stats": site["stats"],
   575	                                 "rejected": [c for c in tried if not c["ok"]]},
   576	                      # the game port, so generate-roster.py needs no second
   577	                      # source of truth for which world this arm is
   578	                      "port": int(conf["server-port"])}, indent=2)
   579	    print(payload)
   580	    # The marker IS the town record: written only after the stamp succeeded, and
   581	    # read on the next run to refuse a second stamp.
   582	    marker.write_text(payload)
   583	    print(f"\n  env for this arm:\n    HOME_X={cx} HOME_Y={y+1} HOME_Z={cz}"
   584	          f"\n    BOARD_X={bx} BOARD_Y={by} BOARD_Z={bz} BOARD_RADIUS=8")
   585

   218	def surface_y(rcon, x, z, hi=200, lo=-64):
   219	    """Highest non-air block in a column, by binary search.
   220	
   221	    THIS REPLACES A FALLING ARMOR STAND that cost up to fifteen SECONDS per
   222	    column. Siting now scores 25 columns per candidate across many candidates;
   223	    at 15s each that is hours per world and eight worlds to do. Binary search is
   224	    ~9 RCON round trips, a few milliseconds.
   225	
   226	    It assumes air above and solid below. That is false inside caves and under
   227	    overhangs -- which are exactly the sites this search exists to reject, and
   228	    they are caught by the slope and canopy tests below.
   229	    """
   230	    # UNKNOWN IS FATAL IN HERE, and this is the call site that proves why the
   231	    # tri-state is worth the noise. A binary search does not return "I could not
   232	    # tell"; it returns a NUMBER, and every caller believes numbers. Against an
   233	    # unloaded column the old boolean read every probe as "not air", took the
   234	    # early return, and reported a ground level of 200 -- which then scored the
   235	    # candidate, chose the town site, and left no trace of having guessed.
   236	    def air(y):
   237	        return matches(rcon, x, y, z, "minecraft:air").require(f"air at {x},{y},{z}")
   238	
   239	    if not air(hi):
   240	        return hi                                   # column is full to the ceiling
   241	    while hi - lo > 1:
   242	        mid = (hi + lo) // 2
   243	        if air(mid):
   244	            hi = mid
   245	        else:
   246	            lo = mid
   247	    return lo
