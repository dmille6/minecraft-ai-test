(promptcache-01) and llama.cpp `llama-server` on the 5080, with the 3090 as a second server. The target is
~107 decisions/min across 80 bots, with p50 <= 2.5 s, p95 <= 5 s and >= 99% schema-valid. At ~13:10Z the owner

  `cache_prompt`, thinking off, and returns the same record keys as before. Each bot is assigned to one server by

## 1. The client change (main `e1e56bf8`, `bots/src/llm.mjs`)

| piece | what it does |
|---|---|
| `parseEndpoint` | `oai+http://h:18080\|alias\|3` becomes api `oai`, url without the prefix, pinned model, weight. A plain entry is Ollama, exactly as before |
| `#postOai` / `oaiRequestBody` | POST `/v1/chat/completions` with `{model, messages, stream:false, temperature, max_tokens, cache_prompt:true, chat_template_kwargs:{enable_thinking:false}, response_format:{type:json_schema, json_schema:{name:decision, schema}}}`. `keep_alive` and `num_ctx` are server-side settings, so they are not sent |
| `oaiResponse` | `content`, `endpoint` (no prefix) and `model` (the server's `--alias`: llama-server returns it whatever name is asked for, verified on b12020). Durations come from `timings` x 1e6. **The meta keys are identical to Ollama's**, because the decision row goes into a `dynamic: strict` index. `cache_n` is not carried |
| `stickyOrder` | The leading run of oai endpoints is one group. A bot's primary is chosen by weighted FNV-1a hash of its name, then the rest of the group, then every other entry in order (the Ollama fallback). The order is unchanged for Ollama-only lists, a single oai server, or a missing name |
| `/health` gate | A **failed** oai endpoint is asked `GET /health` (2 s) before its next real request. It answers 503 while loading and fails at once if the port is dead. A healthy server is never probed |

- Failover is the existing `EndpointPool`. A timeout, a 5xx or a refused connection triggers `markFail` and a
  cooldown (60 s, doubling to 900 s), and the same decision moves on to the next entry.
- Host tooling, main `aa5d5130`. `modelread.py` and `modelrollout.py` probe an `oai+` entry at `/health` without the
  prefix. Before this fix, every probe of an `oai+http://...` URL failed: modelrollout's watch would have rolled back
  every stage after two polls, and modelread's stall message would have called a live server "down".
  - Tests: test_modelread 21/21, test_modelrollout 113/113.
  - Reviews: Codex and Claude APPROVE, 0 blockers.
  - Not installed yet. The canary host's `~/mcai-analysis/modelread.py` is md5-pinned by qwen35c2-01's
    registration, so the install is a release step.
- Review notes, not blockers:
  - Set `OLLAMA_MODEL` to the server's alias, or every oai row carries `model_mismatch`. The canary does this.
  - A `/health` failure doubles the cooldown, like any other failure.
  - modelrollout's load test sends `OLLAMA_MODEL` and probes the first entry only. A weighted two-server list is
    therefore measured as if one server took the whole stage.
