== round 1 (3ee47e3b) Codex: CHANGE
VERDICT: CHANGE

1. **P1 — `scripts/host/staffcensus.py:771`**: Capability is evaluated once at slot end across the entire pool, then applied to all five minutes. A restart retroactively changes earlier minutes; a capable bot far away or flagged can keep the project open. Evaluate capability per minute using that minute’s version and unflagged bots inside 16/12; preserve VOID minutes.

2. **P2 — `scripts/host/staffcensus.py:1132`**: Merging with `newest_per_kind()` discards the persisted predecessor before evaluating historical minutes. Reproduced: an old capable state followed by a fresh off restart changes a pre-restart lookup from capable to VOID. Keep persisted predecessors plus fresh history during census evaluation; compact only when saving.

3. **P2 — `scripts/host/staffcensus.py:449`**: The capability control derives eligibility from the reader it checks and excludes bots missing spawn rows. An entirely empty reader returns `eligible=0, alarm=False`; missing bots can leave a misleading 100%. Preserve independently established build eligibility, count missing evidence as a control shortfall, and alarm when the control cannot be evaluated.

4. **P2 — `scripts/host/staffcensus.py:1128`**: `min(s0, since - PROJECT_LOOKBACK_MS)` bypasses the advertised seed bounds; the fresh query is likewise unbounded by them. Long windows can exceed seven days or touch 10-07. Enforce the bounds on actual mode queries and mark unsupported historical capability VOID.

5. **P1 — `scripts/host/coopread.py:414`**: Daily provenance receives only the window end, so every retained journal observation contributes to the reported “24h” withdrawals and bounds. Pass the window start, retain preceding observations/ops as baseline context, and count only in-window changes and transfers. Add a fixture containing prior-day activity.

6. **P2 — `scripts/host/coopread.py:449`**: Unreadable provenance becomes numerical zeros through fleet aggregation, while zero verified transfers passes its control. Reproduced: `chests other-bot 0-0 of 0 ... controls OK; void 1`. Render unavailable metrics as VOID, distinguish unexercised controls from passing controls, and return nonzero for an unreadable census.

7. **P2 — `scripts/host/coopread.py:298`**: `bot_min` counts every scheduled minute, including missing positions. One snapshot produces 1,440 “covered” bot-minutes and passes `positions_seen`; unknown follow-up also becomes a failed arrival. Count observed and unknown minutes separately, censor incomplete arrival windows, and base controls on actual coverage.

Tests: coopread and sightread passed. Staffcensus passed assertions through the capability controls, then the read-only sandbox blocked its temporary-file fixture. No files modified.

1. **P1, staffcensus.py:93 and :163-183 (`seed_since`): the seed bound counts single-pool restarts as fleet-wide.** `RESTART_PHASES` includes `owner-direct` and `apply-done`. In the journal those rows are per-pool (for example `"pool":"isolated-d"` at 15:29Z). So today's "newest fleet-wide restart" is the isolated-d apply.
   - On the host, seeding from that bound (14:29Z) leaves **49 of 80 bots VOID**.
   - It is hidden today only because the walk uses whichever start is earlier, the bound or `since - 24h`, and bots restart about 7 times a day (552 spawns per kind in 24 h).
   - The state is seeded once and never repaired, so a short seed, or one walk that returns zero rows during an ES gap, keeps those bots VOID until they restart.
   - Fix: make the bound per bot. Walk back (at most 7 d, never before 10-08) until every bot in the track has a spawn row of its current version. Never save a seed with zero rows or with present bots still missing. Re-seed any bot that stays VOID for more than N ticks. At minimum, accept only `promoted` rows that have no `pool` field and say "fleet-wide".

2. **P1, staffcensus.py:146-160 (`capability_control`): the positive control cannot fail on the failures it exists to catch.** A bot is only eligible if its version has emitted `_townindex_mode` and it has a spawn row in view.
   - In the 49-VOID case above it reads **30 of 30, share 1.0, no alarm**.
   - If the mode rows come back empty, eligible is 0, share is None and the alarm is False.
   - Fix: make every bot in the track with a known version eligible, and count VOID as not capable. Apply the 10-minute grace from the version change seen in the track. Alarm when eligible is 0 while bots are present.
   - Add mutant fixtures for empty modes and for a seed that is too short.

3. **P1, staffcensus.py:759-770 with `summarize` :905-925: a VOID capability is counted as a zero.** A slot whose capability is VOID skips the project but leaves the row valid. `valid_h` and the 24-h blocks then count it as 0 assignable. Inside a minute, VOID bots are dropped from `free` as if they were incapable. This contradicts the 6.4 acceptance item. Measured on the fixture:
   - every bot VOID: 7.2 → **0.0** town-h/day, with `valid_share` still 1.0;
   - only fx-A VOID: 7.2 → **4.0**, with the lost minutes labelled `no_material` and `all_flagged_or_building`.

   Fix: give a minute with no capable free bot but a VOID bot at town a `capability_void` reason and take it out of the denominator. Count a VOID slot as a per-project void slot, remove it from `valid_h`, `valid_slots` and `valid_share`, and add a fixture that asserts this.

4. **P1, coopread.py:118-121 and :406: the [P] chest provenance has no window start and no coverage figure.** `provenance(idx, t1)` reads every journal record before t1. The index journal rotates by size (`rotate_mb=4`) and old generations are deleted.

5. **P1, coopread.py:440-451: three of the four controls pass when the reader is blind.**
