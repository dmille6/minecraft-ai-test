codex
The focused test passes **16/16**. The recorded final Paper run is **3/3**, but does not cover deep withdrawal or failed-withdraw fallback. No P1 findings.

1. **P2 — Stock eligibility and requested item disagree.** `bots/src/skills.mjs:3246`; `bots/src/stonesource.mjs:63`  
   The town’s `cobble` view includes cobbled deepslate, but the rewrite always requests literal `cobblestone`; `withdrawVerb` matches that exact item. I reproduced a withdrawal verdict with **192 cobbled deepslate and zero cobblestone**. This replaces a productive gather with a predictably unsuccessful trip. Select an available family member, or require sufficient stock of the requested item.

2. **P2 — The deep probe does not prove the withdrawal route.** `bots/src/skills.mjs:3250`  
   The probe targets within four blocks of **home**, not a stocked chest. Withdrawal independently selects containers; when none are within its initial scan, it calls `home()`, whose `goto` permits digging retries and targets a tighter radius. A successful probe therefore does not establish the promised zero-edit withdrawal path. Probe the actual destination and constrain execution to that route/profile; fall back to gather when it cannot be walked.

3. **P2 — Failure memory lasts 45 seconds, not ten minutes.** `bots/src/cognitive.mjs:1067`  
   `memoryRefuses()` consults the ordinary failed-action cooldown, whose default is **45,000 ms**. There is no dedicated ten-minute withdrawal failure memory. Failures such as `chest_unreachable` deliberately do not accumulate persistent lessons, so the same inaccessible stock can repeatedly trigger trips after this short cooldown. Record the specified ten-minute rewrite suppression independently.

4. **P2 — Admission records gathers that never execute.** `bots/src/cognitive.mjs:1057–1068`  
   `admission.check()` pushes the gather key into its repeat window before the action becomes a withdrawal. Four rewritten proposals can consequently block the original gather fallback, while the executed withdrawals never enter their own repeat window. This is particularly problematic after withdrawal failure: the advertised fallback may already be repeat-blocked. Reconcile admission history with the final action and test the complete rewrite → failure → gather sequence.

5. **P2 — One unmatched rewrite can permanently disable W4 for that bot.** `scripts/host/stonewithdrawread.py:150–154`  
   Matching only examines `pending[b][0]`, and expired entries are never removed. If one rewrite lacks a matching completion within five minutes, every subsequent withdrawal remains unmatched. `fail_share` then excludes those outcomes—or becomes zero—while `exposure_ready` still counts all rewrites. Expire/report unmatched entries, correlate actions explicitly, and require sufficient matched outcomes before declaring exposure ready.

6. **P2 — The read omits the required milestone regression gates.** `scripts/host/stonewithdrawread.py:185–203`  
   The read measures gathering, withdrawals and mining, but never stockpile completion or milestone conversions. A reduction in gathering accompanied by stalled progression can therefore satisfy its reported exposure and defect checks. Add the specified progression measures with pre/post canary/control denominators and positive controls.

7. **P3 — `retry_digs` measures attempted calls, not blocks dug.** `bots/src/skills.mjs:395–401`  
   `digTownStats.wrapped` increments before `bot.dig()` settles, including rejected or interrupted attempts. Reporting its delta as “retry digs” can overstate excavation and mislead the subsequent transit decision. Name it `retry_dig_attempts`, or report confirmed outcomes and associated cells separately.

The goto additions leave the existing retry decisions unchanged on the normal path. The synchronous probe uses only the first generator slice: the installed pathfinder defaults to roughly **40 ms**, despite the supplied 400-ms timeout. It has no explicit 2,000-node bound, and a `partial` result conservatively retains gathering.
