1. **High — bag snapshots silently exclude empty inventories.** `fleetstatus.py:124` uses `latest(require='bot.inventory')`. This field is `flattened`: Elasticsearch indexes its leaf values, so `{}` has no indexed value for `exists` to find. A newly emptied bag can therefore display its older, full inventory; a bot with only empty snapshots disappears from the sample. FakeES treats `{}` as existing, masking this defect. Select snapshots using a reliable snapshot marker and preserve empty inventories; test full→empty transitions. This follows Elasticsearch’s documented [flattened indexing](https://www.elastic.co/guide/en/elasticsearch/reference/current/flattened.html) and [exists semantics](https://www.elastic.co/docs/reference/query-languages/query-dsl/query-dsl-exists-query).

Documents arriving between those operations bypass `max_rows`. I reproduced `max_rows=1` yielding eleven rows before the final mismatch exception. Count within the PIT and enforce the cap during iteration, before yielding excess rows. Add a mutation-between-count-and-iteration test.

5. **Medium — FakeES gives false assurance about text matching.** `test_estelemetry.py` implements `match_phrase` as Python substring membership, whereas Elasticsearch performs analyzed phrase matching. Consequently `t_detail_contains` does not establish the advertised matching behavior. Make the API’s phrase semantics explicit and test token boundaries, punctuation, and case against Elasticsearch or an appropriately faithful fixture. See [Elastic’s full-text query semantics](https://www.elastic.co/docs/reference/query-languages/query-dsl/full-text-queries).
