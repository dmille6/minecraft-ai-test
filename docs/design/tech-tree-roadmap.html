Four Gates to Iron

Revision 2. The first draft of this plan led with a missing smelt verb. Two independent adversarial reviews and a re-measurement moved almost everything, including the top item. What follows is what survived being checked.

Primary endpoint · measured last 24h
11.7% gather success across 28,964 attempts — against a ≥20% START gate. The measurement clock cannot begin until this passes, and no item in the first draft targeted it.

Everything below is ordered by distance to that number. The tech tree is real and worth building, but it is downstream of a gate the fleet has not cleared, and there is no experiment running to be advanced by it.

The prompt line is a treatment, and deleting it is the wrong fix

prompt.mjs:415 exempts pickaxes from the already-have filter, so CAN CRAFT NOW: wooden_pickaxe is advertised permanently — 61.3% of every craft decision the fleet makes.

It is not arm-neutral. Five hive bots write to one pooled fails entry, and the store truncates by fails, so this one key is the heaviest entry in the hive stores and a mid-weight entry in the isolated ones. Removing it deflates hive far more than isolated. That is a shock whose magnitude depends on the treatment, which is exactly what difference-in-differences cannot absorb.

So do not delete it — make it endogenous. Advertise only a pickaxe strictly better than the bot's best held tier, then measure whether a bad convention re-forms without the prompt handing it over. If bots still lock onto one verb at ~60%, that is a real finding about LLM collectives. If they do not, the 61.3% was the prompt talking to itself and was never data. Deleting the line gets neither answer.

Sequence

Phase 0

Instruments

nothing ships to bots

None of this changes behaviour. All of it decides whether later numbers mean anything.

  • Two test files hang forever. They sit alphabetically before prompt-usage-coverage and affordance-contract — the exact tests that would police a new skill's observation contract. Ship smelt today and its guard rail runs silently unrun.
  • Four incompatible bot-hour denominators; no two reports have ever been comparable. One gate script still hardcodes 40 bots against an 80-bot fleet.
  • The placebo arm's board visits emit no telemetry at all. The control is currently unobservable.
  • Pickaxe durability is absent from inventory telemetry, so every claim about tool budget is unfalsifiable.
  • Two amendments are owed and unwritten — board non-compliance, and a declaration that the observation text is a treatment surface.
Phase A

The scaffold floor

repair · highest yield

The single cheapest high-yield change available, and it was missing from the first draft entirely.

exit-contract.mjs:101 sets blockReserve = max(8, ceil(debt/4)). At debt=1 that demands nine scaffold blocks for a one-block climb. Measured: 580 refusals carrying a stated debt, median debt 1, 69% at debt ≤ 4. The floor, not the depth, is doing the refusing.

At the deep end the same formula sets needUses=62 at y=15 while a wooden pickaxe has 59 durability — a wooden-tier bot is arithmetically forbidden from reaching iron. Stone-tier passes, which is why bots reach y=−55 at all.

Fix
max(min(FLOOR, debt), ceil(debt/4)). Written up months ago, never built.
Metric
mine refusals by reason per bot-hour; share of refusals at debt ≤ 4. High-N, moves within an hour.
Also here
mine's “within 4 blocks of home” precondition — 473 refusals, the largest single reason.
Phase B

Gather success

the actual endpoint

11.7% against a 20% gate, across 28,964 attempts — the largest verb in the fleet and the number the experiment is defined on. It needs its own diagnosis before anything is built: failure-reason census first, fix second.

Metric
Gather success per bot-hour, by failure class and by depth band.
Note
Any series spanning 2af8251 compares two definitions of success — the gather scoring fix changed what counts. Restrict to post-fix windows.
Phase C

Craft table reachability

the one canary-able item

craft accepts a table found within 32 blocks regardless of whether it can be reached, and the self-placement fallback at skills.mjs:1717 is guarded by !table — so it is unreachable precisely when a distant table is visible. Bots underground are sent to walk to a table through 40 blocks of rock while carrying their own.

Metric
no_path per craft attempt (should collapse) and craft attempts per bot-hour (must not fall — if it does, the skill was short-circuited, not fixed).
Co-primary
Decisions per bot-hour. This removes up to two 12-second pathfinder walks from a 30-second cadence, so it is secretly a cadence change — and cadence spread is itself a START gate.
Phase D

Endogenous affordance

treatment · own amendment

The strictly-better-tier change described above. Fleet-wide at a declared boundary, nothing else in the deploy, pre-specified predictions.

Cannot be canaried
The effect lives in the pooled store, and one canary pool is one arm — n=1.
Primary
Shannon entropy of the action-key distribution per bot-hour. Thousands of decisions hourly; non-tautological because you are measuring whether the tail broadened, not whether the deleted line stopped appearing.
Prediction
Entropy rises more in hive than isolated. Falsifiable, pre-registered, and it is the whole experiment.
Phase E

Smelt

new capability

Roughly 150 lines of core mineflayer, no plugin. It moved from first to fifth — not because it is wrong, but because it is downstream of a descent gate and a placement gate, and because the fleet has not passed the gate that starts the experiment.

The payoff is nonetheless already banked: 18 of the 19 bots holding raw iron also hold a furnace and fuel, across all four arms. That is 33 raw iron and about eleven iron pickaxes one verb away.

Gate it on
A measured opportunity rate — bot-hours holding raw_iron ∧ furnace ∧ fuel. Measurable today, costs one query. If it is near zero, smelt is another rung behind a gate nobody passes.
Metric
Three-stage funnel: opportunity → proposals per opportunity → successes per proposal. Never “bots holding ingots”.
Traps
recipesFor(iron_ingot) returns [] (minecraft-data #290, open since 2020). takeOutput() throws on an empty slot. fuel/progress are null until the first update, which can report a spurious zero. Take raw_iron, never iron_ore.
Phase F

Prospect

the experiment’s real surface

The collective already shares ore coordinates in the prompt and has no verb that can act on them. Verified post-scoring-fix: gather iron_ore is 29 attempts and 0 successes in the last 24 hours, coal_ore 91 and 0. Ore is buried by definition and gather refuses buried candidates, so iron is obtained only by accident while tunnelling.

“Where is the iron” is a belief about where payoff is: shareable, actionable, and capable of being wrong. A collective that shares it can lock onto a bad answer faster than one that does not.

Blocked on
Parent claim ids. Without them, five bots agreeing is not five observations if four copied the first, and hive will look better-informed purely by echo.
Unit
The belief, not the pool — which turns n=4 into n=(pools × beliefs) and is the sample-size fix this design has been missing.
Design risk
Instrument whether a coordinate came from self or shared memory, and separate used a shared coordinate from successfully dug to it. Otherwise belief propagation and motor competence move together and neither is measurable.

What not to build

The server runs difficulty=peaceful, pre-registered and load-bearing for two death endpoints. That single fact voids an entire category of obvious-looking work.

  • combat / armourNo hostile spawns. Zero mob deaths in fleet history — already misread once as “our reflex layer prevents mob deaths.”
  • torches / lightingNo spawn suppression to buy. 57 bots carry torches; place torch has been attempted twice, ever.
  • food / farming / auto-eatHunger does not deplete on peaceful. eat: 161 lifetime calls, 100% no-effect.
  • dig_down / go_upDuplicates mine, which already staircases. The defect is a precondition, not a missing verb.
  • mineflayer-toolLast published 2022, pre-1.19. Reintroduces a digTime bug the codebase already patches.
  • LLM critic loopThe evidence gate is strictly better. A critic would mark a smelt successful on an empty furnace.

The thing that outranks all of it

The board arm is not delivering its treatment. Two board calls in 26,418 decisions across twenty bots in 24 hours — 0.08 per thousand. Worse, scope === 'board' gives private lessons plus auto-pooled world facts, which is the placebo condition. And the placebo arm's board visits log nothing at all.

So the dose ladder currently reads: hive (dose), board (= placebo), placebo (invisible), isolated (control). That is a two-arm experiment with two mislabelled arms. No amount of tech-tree work fixes it, and deciding it is Phase 0 work.

Rules that hold across every phase

  • One canary pool, ever. The tripper matches canary_pool literally; two canaries means three versions means a halted fleet. Teardown is two steps and half a teardown is silently wrong in both directions.
  • A canary pool is n=1. The pool is the experimental unit, so five bots is one observation. It answers “does it crash” and almost nothing else.
  • Difference-in-differences, never canary-vs-fleet. A good deploy was already rolled back once on cross-sectional noise, because the pool happened to contain two chronic emitters of a pre-existing error.
  • Reject tautological metrics. If the number moves because you shipped the thing that produces it, it is compliance with your own edit, not evidence.
  • Probe a known-positive before believing a zero. Two detectors in one day returned confident, uniform, wrong answers — one read a field that does not exist.
