### Things that are easy to get wrong here

- **systemd instances are ROLE names** — `scout scout2 miner gatherer gather2`,
  never display names. `systemctl restart mcbot@Scout01` creates a phantom unit
  that fails forever while the real bot keeps running. This has happened twice.
  `lab01:/srv/mcbots/bot-manifest.json` publishes the mapping.
- **Interface names differ per cluster node.** rprox1 uses `lan/ten/sfp`;
  rprox3a uses `nic0..nic4`. The lab bridge is `vmbr193` on `nic2.193`.
- **Storage is node-scoped.** rprox1 has 793G on `local-lvm`; rprox3a has 137G.
  The lab lives on `data-zfs` (6.4T free).
- **The operator is on the VPN (192.168.2.x), not the lab VLAN.** Every service
  needs both ranges in ufw. Docker-published ports bypass ufw entirely and are
  protected by their bind address instead.
- **Paper is pinned to 1.21.8, not 1.21.11**, because of an open mineflayer
  issue reporting pathfinding/jumping failures specifically on 1.21.11. This is
  a live confound — see §4.

## 2. What was wrong with the old fleet, and what fixed it

Over 16 hours the proof-of-concept produced **81 deaths, 80 of them falls, all
at y20-39**, with `goto` succeeding 3% of the time. Every liveness check
reported healthy throughout. Three defects, all the same shape — **a value
reported rather than measured**:

1. **`goto` classified its own failures by regexing its error prose.** The
   pattern also matched our own wrapper message `pathfinding exceeded 25000ms`,
   so 393 expired travel budgets were recorded as "no route exists". The
   pathfinder returned `NoPath` **zero** times in that window. Now classified on
   `e.name`, the library's typed error contract.

2. **The reflex layer's stuck detector calls `bot.pathfinder.stop()`.** Verified
   against mineflayer-pathfinder 2.4.5: `path_stop` is emitted **only** by
   `stop()`, which only our code calls. So `goto()` rejected with `PathStopped`
   rather than our AbortError, `e.aborted` was undefined, and **596
   interruptions we caused were charged to the skill as failures**.

3. **Those false labels were persisted and enforced.** All five bots had
   `home:{}` in their avoid table, four past the block threshold, one at 24
   failures. The fleet taught itself that walking home was impossible using
   evidence it manufactured, and the admission gate enforced it. 30 movement
   rules purged (`scripts/purge-corrupt-movement-lessons.py`).

`path_interrupted`, `path_budget` and `goal_changed` no longer write lessons at
all. A lesson claims "this does not work"; only a failure the **world** caused
can support that.

## 4. The confound, stated plainly

**The improvement cannot be attributed.** Five things changed at once:

- Minecraft 1.21.11 → 1.21.8 (open mineflayer issue on 1.21.11)
- a freshly pregenerated world (no live chunk generation mid-trial)
- 30 corrupted movement lessons purged
- self-inflicted failures no longer write lessons
- an LLM `num_ctx` mismatch fixed that had been timing out every request

Some of the change is also **definitional**: self-inflicted interruptions now
return `aborted` rather than `failed`, so yesterday's 3% and tonight's 33% were
not computed under identical rules.

One number does argue for real behavioural change: the fleet takes **~70 skill
actions/hour** now versus **~375/hour** yesterday. Fewer actions, far higher
success — the signature of a fleet that stopped thrashing on blocked actions,
not one that merely relabelled its failures.

**Do not conclude "our fixes worked" from this data.** The fixes demonstrably
corrected *measurement*; the measurement now says things are better. Those are
different claims.

## 5. What is watching while nobody is

- **Death circuit breaker** (`/usr/local/bin/mcai-tripper`, 5-minute timer on
  ctl01). 2 fall deaths per bot per 30m stops that bot; 5 fleet-wide per 30m or
  4 at y20-39 per 60m stops all. Reads **only** raw death events, because the
  label pipeline has proven it can manufacture evidence. It only ever STOPS —
  never tunes, never deploys.
- **Commit-mismatch trip.** Bots disagreeing on code version (partial deploy) or
  running something the trial manifest does not declare = uninterpretable, so
  stop. The version string is `<sha>+<digest of the .mjs actually loaded>`.
- **Alerts** to ntfy → phone, plus journald always.
- **Independent observer** (`mcai-observer` on mc01): server-side RCON sampling
  of position/health every 10s, computing displacement itself. Nothing in the
  agent stack contributes to that number.
- **Evidence archive** on evd01, pulled every 5 minutes over a forced-command
  rrsync key that refuses a shell.

## 6. What to do next, in order

### The weekend: prove it reproduces

| run | change | question |
|---|---|---|
| **1. A/A** | nothing | **does tonight reproduce?** |
| 2. lessons off | disable the lessons store | did lessons help, or just stop hurting? |
| 3. old lessons | restore the purged rules | were corrupted lessons the main drag? |
| 4. MC 1.21.11 | version only | was it a mineflayer bug all along? |

Same metrics, same guard thresholds. **A trial that trips the guard is a valid
result, not an inconvenience.** Run 1 comes first and is non-negotiable: if two
identical runs diverge, nothing downstream means anything.

### Next week: the smallest causal observer

A Paper plugin, scoped tightly — damage cause, death cause, block break/place
outcome, inventory change, position. That turns *"the bot says it failed"* into
*"the server says what happened"*. RCON polling measures state and never
causation: it can say a bot fell, never what it fell from.

Plus per-event causation on `block_updated`: changed-block position, distance
from the planned path, who caused it, what happened next.

**Do not engineer against `block_updated` yet.** 41% says paths are invalidated
by world changes. It does not say the invalidation is wrong — it may be the
pathfinder reacting correctly to a bot mining. Instrument first.

### Explicitly not now

- **BlueMap render** — staged on evd01, deliberately not started. Hours of IO,
  resolves no uncertainty.
- **Waypoint nav graph** — `goto` went 3% → 33%; the problem may have shrunk.
- **Cooperation or a sixth bot** — the three existing roles have never been
  demonstrated to behave differently. Adding variety before proving
  differentiation adds noise.
- **Demo polish** — the dashboard is sufficient. Do not polish before you can
  reproduce.
