# PROTECTED PATHS -- the fun-mode tier-3 list (docs/PROCESS-fun-mode.md § Tiers; OWNER 2026-10-28).
#
# A change that touches any line matched here is TIER 3: two review engines, a fleet canary, the
# generic read. Everything else is tier 1 or 2. Risk is the test, not size: a one-line change to
# mining depth is tier 3, a 600-line building feature is not.
#
# Decided by scripts/lib/protected.py (`python3 scripts/lib/protected.py --base origin/main`), which
# the showcase gate (W2) and the canary loop (W4) call. Do not re-implement the match elsewhere.
#
# FORMAT, one entry per line:
#   <glob>                    every line of every matching file
#   <glob>::<function glob>   only lines inside those TOP-LEVEL functions of that file
#   tooling: <either form>    tier TOOLING: a host script that never runs on a bot. Two engines,
#                             no fleet canary (there is nothing on the bots to canary).
# Globs: `*` stays inside one path segment, `**` crosses segments, `?` is one character.
# A changed line in a `::` file is attributed to the nearest top-level declaration above it
# (function, class, const/let/var -- so a safety CONSTANT is listed by its name, like a function).
# Each hunk's old-side lines a, a+1 are attributed too, so a declaration INSERTED inside a listed
# function is still that function's change. An import a listed function depends on is protected
# when changed or deleted (add a new import line instead of editing one); a side-effect import is
# protected when added. A row of a top-level table (SKILLS, SKILL_CONTRACTS) whose key or `run:`
# names a listed symbol is protected. A change to a `::` file with no line hunks (pure rename, mode
# change, binary) counts as protected: it cannot be attributed. protected.py's docstring has the
# exact rules.
# A file path that stops existing fails bots/test/protected-paths.test.mjs, so a rename cannot
# quietly drop something out of protection. Adding to this list is a decision; so is removing.
